THE FULL PRODUCT VISION

“Help me understand this company before I invest.”

Eventually, EquityLens will connect financial history, current developments, management commitments, industry conditions, and future scenarios. Every important conclusion should be inspectable through its evidence and assumptions.

Our first dependency is trustworthy source material. That is the layer we have built now.

02 / Current capabilities

What you can actually do today

COMPANY WORKSPACES

Choose Microsoft or Infosys

Each company has its own evidence library. Infosys’s NSE, BSE, and NYSE listings point to one company, while retaining their distinct trading currencies and security types.

SOURCE INGESTION

Import or upload a document

Import a curated annual report, or upload a PDF, HTML file, or UTF-8 text file up to 25 MB. Attach a title, stable document key, and any known source dates.

EVIDENCE SEARCH

Find relevant passages

Search words such as “revenue” or “operating profit.” PostgreSQL searches the extracted text and returns passages with their document versions and source locations.

SOURCE HISTORY

Inspect the original and its revisions

Download the preserved original. A revised upload gets a new content version. Reimporting identical content under the same document identity returns the existing version.

Streamlit

The interface you click. It calls the API and displays its results. Application logic is written in Python.

FastAPI

The backend service. It checks inputs and coordinates source access, extraction, storage, and search.

PostgreSQL

The main database, running inside Docker. Its full-text search finds evidence already in your library.

Where are LangGraph, embeddings, MCP, and the language model?

They belong to later stages. The current build has no model generating answers, no embedding-based retrieval, no LangGraph workflow, and no MCP server. Source adapters are ordinary Python functions today. We can expose reviewed tool contracts through MCP when the underlying data operations are ready.

The existing search uses PostgreSQL full-text matching. It retrieves evidence; it does not synthesize an investment conclusion.

04 / End-to-end flow

Follow a report through the system

You choose a company and a source

For example, select Infosys and import its curated annual report. The backend checks that the catalog document belongs to Infosys.

The source is checked and downloaded

The adapter uses a reviewed HTTPS destination. Redirects to other destinations are rejected. Uploads are checked for supported type and size. An uploaded source URL is stored as metadata, not automatically fetched.

The original is preserved

SHA-256 creates a content fingerprint. The source bytes are stored under that fingerprint. Identical bytes can share the stored object; document identity remains tied to the company and source.

A separate process extracts the text

PDFs use pypdf; HTML uses Beautiful Soup. HTML scripts and styles are removed from extracted text. A timeout bounds the extraction run. A scanned PDF with no readable text is flagged for review.

The text becomes evidence passages

Text is split into roughly 1,800-character passages with overlap. PDF passages keep their page number; passages also keep character positions in the extracted text.

Records are committed to PostgreSQL

The document version, content hash, parser version, passages, and import outcome are stored. Failed imports retain an error record. Imports are currently synchronous; crash recovery through durable workers is future work.

You search and inspect the evidence

A search retrieves matching passages for the selected company. Each result links to its preserved original and, when supplied, the public source website.

Original files

Live in data/objects/. Their filenames are derived from content hashes rather than user-supplied filenames.

Database records

Live in the PostgreSQL Docker volume. A complete backup will need both database records and original source objects.

Why don’t we just store “revenue = 100”?

Because 100 could mean USD, INR, INR crore, a quarter, a year, or a year-to-date period. It might describe the parent company alone or the consolidated group. It might also be a revised value.

The SEC layer already retains reported units, taxonomy concepts, dates, accessions, and decimal values. Mapping these into comparable metrics with verified reporting basis is the next milestone.

06 / Reliability decisions

How we keep evidence traceable

Revisions remain visible

Uploading revised content using the same document key creates another version. The earlier original and its passages remain available.

Dates keep their meanings

Reporting period, publication date, and collection time are separate. Collection today does not imply publication today.

Missing extraction stays visible

Textless PDFs are marked as needing review. The app does not invent text for pages that need OCR.

Company boundaries are explicit

Search filters by company identity. Microsoft’s passages do not appear in Infosys’s library.

What does “as of a date” mean in this build?

The API’s optional as_of search is deliberately strict: a document must have a publication date on or before the cutoff and must have been collected by then. Unknown publication dates are excluded.

This answers “what evidence had this system observed by that date?” It does not claim to reconstruct everything publicly available in the past. The control is currently an API feature, not an interface option.

Production maturity: this milestone implements several foundations for reliability. It still needs authentication, user isolation, durable jobs, resource quotas, stronger parsing isolation, monitoring, and tested recovery before public deployment.

08 / Hands-on walkthrough

Try the current app in five minutes

Open the workspace

Visit localhost:8501. Choose Infosys in the sidebar.

Search for “revenue”

In Evidence search, type revenue. Read a result and inspect its PDF page location. The result is a source passage, not an AI-written conclusion.

Inspect the source

Open Document library. Expand the annual report, inspect its metadata and content hash, preview extracted evidence, and download the preserved report.

Compare the other company’s workspace

Switch to Microsoft. Repeat the search. These results come from Microsoft’s imported annual-report HTML.

Try version history

Upload your own text document with a stable key. Reupload it unchanged to see duplicate handling. Edit its contents and reuse the key to create a new version.

Restart the app after restarting your computer

Start Docker Desktop, then open the EquityLens folder in VS Code.

Terminal 1 — database and API

docker compose up -d db
.\.venv\Scripts\python.exe -m equitylens.cli serve

Terminal 2 — interface

.\.venv\Scripts\python.exe -m streamlit run ui.py

The setup and initial database migration have already been completed on this computer. The README contains the full setup commands for a fresh environment.

This HTML guide is self-contained and opens offline. Its local-app links require the EquityLens services to be running. It does not read your database or credentials.

10 / Build roadmap

How this becomes your research product

1. Evidence foundation BUILT

Company identity, report imports, original preservation, versions, evidence search, and source inspection.

2. Financial extraction and validation NEXT

Preserve table structure, extract core metrics, verify units and reporting basis, reconcile values, and calculate ratios from traceable inputs.

3. Evidence-backed AI research PLANNED

Add a model and durable workflow that can ask research questions, retrieve evidence, verify claims, and produce cited reports.

4. Management delivery and developments PLANNED

Track announced projects, targets, deadlines, revisions, and outcome evidence. Add permitted news and event sources.

5. Scenarios and thesis tracking PLANNED

Model explicit assumptions, compare scenarios, and monitor changes that support or weaken a user’s investment thesis.

6. Public-service readiness PLANNED

Complete authentication, access isolation, budgets, source-rights review, monitoring, backups, recovery tests, and deployment evaluation.

The next concrete outcome

For one company, select a reported revenue value and show its currency, scale, reporting period, reporting basis, and original table location. Then reproduce its growth calculation from verified inputs.

That turns searchable documents into dependable financial data—the prerequisite for useful AI analysis.
